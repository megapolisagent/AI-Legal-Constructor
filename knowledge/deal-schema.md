# Схема сделки — справочник для агента

Source of truth бизнес-требований — `MAIN_ASSISTANT\knowledge\projects\legal-contract-constructor-handoff.md`
(v1.1), этот файл — рабочий конспект под рукой в самом репозитории (progressive disclosure:
подгружай его, когда собираешь/проверяешь `deal.json`, не при каждом сообщении в диалоге).

|---|---|---|---|
| `deal_id` | строка | генерируется | `deal_<8 hex>` |
| `deal_type` | `"аренда"` \| `"продажа"` | да | |
| `status` | строка | нет | `draft` по умолчанию |
| `agent_id` | строка | нет | кто ведёт сделку |
| `address` | строка | **да** | |
| `cadastral_number` | строка | **да** | |
| `property_type`, `area`, `rooms`, `ownership_basis`, `encumbrances` | строка | нет | |
| `participants` | список Participant | **да, минимум 1** | см. ниже |
| `price` | строка | **да** | |
| `payment_schedule`, `deposit`, `term`, `special_conditions` | строка | нет | |
| `agency_name`, `agency_inn`, `agency_ogrn`, `agency_signatory` | строка | нет | `agency_name` по умолчанию «Мегаполис» |

## Participant — участник (динамический список, не пара!)

| Поле | Тип | Обязательно | Примечание |
|---|---|---|---|
| `participant_id` | строка | генерируется | `p_<8 hex>` |
| `side` | `"сторона объекта"` \| `"сторона контрагента"` | да | |
| `full_name` | строка | **да** | |
| `passport_data` | строка | **да** | |
| `registration_address`, `contact`, `representative` | строка | нет | |
| `ownership_share` | строка | нужна, если у стороны объекта больше 1 участника | доля в праве |
| `is_married`, `is_minor`, `has_other_co_owners` | bool | нет | триггеры согласий, см. ниже |
| `commission_value` | строка | нет | % или сумма, может отличаться по участнику |

**consent_flags — ПРЕДПОЛАГАЮ**, что именно эти три признака определяют потребность
в согласиях — точный список оснований **[УТОЧНИТЬ] у юриста** (handoff §9), не решается
агентом самостоятельно.

## Правила состава комплекта (handoff §5) — логика в `scripts/rules.py`, не меняется

- 1 **комиссия** на каждого участника (обе стороны).
- 1 **основной договор** на сделку (если есть хоть один участник).
- 1 **акт приёма-передачи** на сделку.
- **согласие** — по одному на каждый выставленный флаг (`is_married` → согласие супруга,
  `is_minor` → согласие органа опеки, `has_other_co_owners` → согласие содольщика).

Пример: 2 собственника в долях (один в браке) + 1 покупатель → 3 комиссии + 1 основной
договор + 1 акт + 1 согласие супруга = **6 документов**.

## Обязательные поля перед сборкой (`scripts/rules.py`, `missing_fields`)

Deal: `address`, `cadastral_number`, `price`. Participant: `full_name`, `passport_data`,
плюс `ownership_share`, если у стороны объекта больше одного участника.

## Что явно НЕ входит в задачу агента (handoff §10, §3)

- Юридический текст самих шаблонов — решает Мария/юрист.
- Точный список оснований для согласий — решает юрист.
- Перевод шаблона `draft` → `active` в `templates_docx/registry.json` — отдельное решение
  владелицы, не часть сборки конкретной сделки.
- Автоматическое подписание — все документы выходят как черновики на юридическую проверку.
